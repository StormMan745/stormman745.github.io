# PetCare для Android и iPhone

Мобильные проекты на Capacitor 8 используют существующий сайт как локальный интерфейс. Исходники сайта остаются в корне, мобильная интеграция — в `src/native.js`. Сервер, аккаунты и данные остаются общими с сайтом. Идентификатор приложения: `app.petcare.companion`, версия Android 1.0.1 (versionCode 2).

## Подготовлено

- Android-проект Gradle и iOS-проект Xcode со Swift Package Manager.
- Локальная сборка интерфейса и того же закреплённого Supabase SDK 2.118.0 без загрузки с CDN. В пакет входят только необходимые файлы, без `.tools`, серверных функций и зависимостей сборщика.
- Системные уведомления по напоминаниям, обработка кнопки «Назад» Android, обновление сессии при возвращении в приложение.
- Системная геопозиция, просмотр документов, меню отправки/сохранения файлов и коллажей, системная печать медицинской карточки и оригиналов документов.
- Иконки PetCare, экраны запуска, описания разрешений iOS, privacy manifest для используемых API.

Интерфейс поставляется внутри приложения. Вход, синхронизация, документы из облака, карта и ассистент требуют интернета. Это не полностью автономный режим работы с данными.

## Напоминания

В мобильном приложении используются **локальные уведомления**, а не браузерная push-подписка и не FCM/APNs. Включаются пользователем в разделе напоминаний. На устройстве планируются ближайшие 60 событий с заполненным временем для всех питомцев текущего аккаунта; очередь обновляется при изменении данных и возвращении в приложение. Отмеченные события пропускаются. При выходе или смене аккаунта запланированные события очищаются.

На Android 8+ обычные и ежедневные события, а также тест используют отдельный канал `petcare_reminders_v1` («Напоминания PetCare»): высокий приоритет, системная мелодия уведомлений и вибрация. Канал создаётся до планирования. Его ID постоянный; существующие настройки владельца не сбрасываются. Новое событие получает отдельный идентификатор, а сдвиг очереди не меняет ID оставшихся событий. Это предотвращает подавление звука Android при замене старого видимого уведомления. Старое видимое пробное сообщение удаляется перед новой проверкой.

В блоке уведомлений APK есть кнопка «Настроить звук уведомлений», открывающая системные настройки канала. Приложение показывает отключённый звук канала, нулевую громкость и беззвучный режим, если они определены системным API. Оно не включает звук вопреки настройкам владельца и не обходит «Не беспокоить». При возвращении из настроек статус и расписание обновляются. После установки нового APK включите уведомления и выполните проверку; оценить фактический звук можно только на телефоне. Обновление сайта не изменяет уже установленный APK.

Длительное отсутствие запусков может исчерпать очередь. Изменения с другого устройства поступают в расписание после загрузки данных в приложении. Без времени событие остаётся в календаре, но уведомление не планируется. Доставка может задерживаться системой; разрешение точных будильников Android не запрашивается. Для серверной доставки независимо от запуска приложения следующим этапом нужна интеграция FCM/APNs и серверных токенов устройств.

## Сборка

Нужен Node.js 22 или новее. Все версии зависимостей закреплены в `package-lock.json`.

```sh
cd mobile
npm ci
npm run check
npm run sync
```

`build` пересоздаёт только `mobile/www`; `sync` переносит сборку в оба мобильных проекта. После изменения `clinics.js` сначала выполните из корня `node tools/build-clinics.cjs`.

### Android

Нужны JDK 21 и Android SDK (platform 36 и build-tools 36.0.0). Открыть проект: `npm run android` из папки `mobile`. Собрать пробную версию из PowerShell в корне проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File mobile/scripts/build-android.ps1
```

Скрипт использует установленные инструменты из `JAVA_HOME`/`ANDROID_HOME` либо локальные инструменты из `.tools/petcare-jdk21` и `.tools/petcare-android-sdk`. APK копируется в `mobile/releases/PetCare-android-debug.apk`. Это подписанная отладочным ключом сборка для тестовой установки, не релиз для магазина. Для публикации нужен собственный постоянный ключ подписи и release/AAB.

### iPhone

На Mac установите Xcode, выполните `npm ci` и `npm run sync` в папке `mobile`, затем `npm run ios`. В Xcode выберите свою команду в Signing & Capabilities и подключённый iPhone. Для TestFlight выполните Archive и загрузку через Organiser со своей учётной записью разработчика Apple. На Windows iOS-проект подготовлен, но компиляция, подпись и проверка на устройстве не выполнены.

## Проверки и текущие границы

`npm test` проверяет планирование дат, повторений, выполненных событий, лимит очереди и несколько питомцев. `node mobile/tests/native-smoke.cjs` из корня использует уже имеющиеся Playwright в `.tools/preview` и Chrome на этом компьютере: проверяет запуск мобильной сборки, отсутствие Service Worker, вызовы просмотра/отправки/печати и очистку уведомлений между аккаунтами. В этом тесте системные API имитируются. Существующая проверка документов: `node tools/check-documents.cjs`.

Файлы для системного просмотра и отправки записываются во временный кэш приложения; он очищается при следующем холодном запуске и сбросе аккаунта. Экспортированная пользователем копия принадлежит выбранному приложению/хранилищу и не удаляется при выходе из PetCare.

Пока не проверены вход настоящего пользователя, системные диалоги на физических Android/iPhone, доставка при закрытом приложении и поведение файлов/камеры на этих устройствах. До магазинного релиза также нужны публичная политика конфиденциальности, удаление аккаунта, декларации данных (включая передачу текста ассистенту), материалы страницы приложения и настройка релизной подписи. App Store/Google Play публикация в этой работе не выполнялась.

Официальные справочники: [Capacitor](https://capacitorjs.com/docs), [локальные уведомления](https://capacitorjs.com/docs/apis/local-notifications), [требования среды](https://capacitorjs.com/docs/getting-started/environment-setup).
