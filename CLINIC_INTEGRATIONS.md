# Передача данных из клиник в PetCare

PetCare принимает приёмы и текстовые результаты обследований от клиники через защищённый серверный endpoint. Для начала передачи администратор клиники должен подключить свою систему учёта к этому протоколу и проверить соответствие владельца и пациента. Поддержка endpoint не означает, что какие-либо реальные клиники уже подключены. Внешних отправок сообщений клиникам приложение не выполняет.

## Для владельца

Откройте «Здоровье → Данные из клиник», выберите питомца и укажите название клиники. После согласия создаётся отдельное разрешение сроком на год. Передайте скачанную инструкцию администратору этой клиники. Ключ показывается только при создании; восстановить его из базы нельзя. Если ключ потерян, отзовите разрешение и создайте новое.

До первой передачи показывается «Ожидает настройки клиникой и первой передачи». Затем доступны число полученных записей и время последней доставки. Отзыв останавливает новые записи, уже сохранённые остаются. Удаление питомца автоматически отзывает его разрешения. Клиника с таким ключом не может читать профиль, переписку, другие записи или изменять данные другого питомца.

## Для клиники

Метод: `POST https://qexiyikdmdbdxgusqnee.supabase.co/functions/v1/petcare-clinic-sync`.

Заголовки: `Content-Type: application/json`, `Authorization: Bearer <выданный владельцем ключ>`.

Запрос выполняет сервер клиники, без заголовка Origin. Пароль владельца, пароль Госуслуг и ключ Supabase не нужны. Не помещайте ключ в URL, логи или общедоступный JavaScript.

```json
{
  "eventId": "your-stable-visit-id",
  "record": {
    "kind": "visit",
    "date": "2026-11-12",
    "name": "Приём ветеринара",
    "doctor": "Врач клиники",
    "note": "Заключение из медицинской карты",
    "diagnosis": "Диагноз врача",
    "prescription": "Назначения врача"
  }
}
```

Для обследования: `kind: "examination"`, обязательное поле `results` (текст результатов), необязательное `labName`. `date` — действительная дата `YYYY-MM-DD`. `name` и `eventId` обязательны, до 160 символов; doctor/labName — до 160; note/results — до 16 000; diagnosis — до 4000; prescription — до 8000. Весь UTF-8 JSON ограничен 64 KiB. Поля userId/petId/id/source из запроса не задают получателя: аккаунт и питомец берутся из разрешения на сервере.

Ключ предназначен для одного пациента, клиника сопоставляет его со своей картой только после проверки владельца. Нельзя отправлять по этому адресу общую выгрузку всех пациентов. Сервер PetCare не скачивает произвольные URL из запроса. PDF, изображения, внешние ссылки и бинарные вложения этим endpoint не импортируются; владелец может загрузить оригиналы через раздел документов.

Успех: `200 {"accepted":true,"duplicate":false,"recordId":"..."}`. Повтор с тем же eventId и теми же данными возвращает duplicate=true. Исправления отправляйте новым eventId: тот же ID с другим содержимым даёт 409, а пользовательские изменения не перезаписываются. Повторная доставка удалённой владельцем записи не восстанавливает её.

Ошибки: 400 — формат, 401/404 — ключ недоступен, 403 — запрос из браузера, 409 — конфликт eventId, 413 — слишком большой запрос, 415 — тип содержимого, 422 — квота профиля или недопустимая запись, 429 — ограничение частоты (Retry-After), 503 — временная ошибка. Повторяйте временные ошибки с задержкой и тем же eventId. Ограничение: 60 запросов в минуту и 1000 в сутки UTC на разрешение. При 401/404 нужна новая настройка с владельцем.

При сохранении используется та же блокировка аккаунта, что и при обычной синхронизации. Запись и квитанция о событии сохраняются одной транзакцией. Данные приходят в существующий healthRecords, доступны печати, поиску и контексту ассистента. Публикация petcare_data и существующая Realtime-синхронизация обновляют открытое приложение; офлайн-изменения пользователя объединяются обычным механизмом синхронизации.

## Системы учёта и государственные сервисы

Протокол доступен для любой клиники, способной выполнять исходящие HTTPS-запросы. Это универсальный приёмник, а не готовый адаптер каждой медицинской системы. Например, Ветменеджер документирует [REST API](https://help.vetmanager.cloud/article/3029) и [вебхуки](https://help.vetmanager.cloud/article/3002). Адаптер клиники должен преобразовать её событие в описанный формат; прямой необработанный вебхук Ветменеджера этот endpoint не принимает. Ключи широкого доступа к системе клиники в приложении владельца не запрашиваются.

Официальный автоматический доступ PetCare к ветеринарным данным Госуслуг или mos.ru не подключён. Вход через ЕСИА сам по себе не предоставляет доступ к таким сведениям; внешнее подключение зависит от официального допуска и доступных интерфейсов оператора. В интерфейсе даны ссылки на личные кабинеты и загрузка документа, если портал позволяет его скачать. Пароли государственных сервисов в PetCare вводить не требуется. Наличие ветеринарной карты у портала не означает наличия открытого API для её чтения сторонними приложениями.

Проверки: `npm --prefix tools run test:clinic-connections`; административный SQL-пробник `tools/sql/clinic_record_connections.sql` создаёт только синтетические аккаунты в транзакции и откатывает их. В работе не использовались настоящие записи клиник и учётные данные государственных порталов.
