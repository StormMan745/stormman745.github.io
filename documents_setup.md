# Документы питомца

Раздел доступен из «Здоровья», профиля питомца и каждой медицинской записи в истории.
Поддерживаются PDF и сканы JPEG, PNG, WebP до 10 МБ каждый. Оригинал не сжимается.
Название, тип, дата и связь с медицинской записью редактируются отдельно от файла.
Документы группируются по приёмам: рядом показываются диагноз, назначения и заметки.
Удаление медицинской записи оставляет документ в библиотеке без действующей привязки.
При удалении питомца удаляются его документы и оригиналы файлов.

## Хранение

- Логика интерфейса: [documents.js](documents.js), стили: [documents.css](documents.css).
- Метаданные: `public.petcare_documents`, защищённая RLS таблица.
- Оригиналы: закрытый Storage bucket `petcare-documents`, путь `user_id/document_id/original.ext`.
- Чтение, добавление, изменение и удаление ограничены владельцем. Менять владельца, питомца и путь существующего документа через API нельзя.
- Просмотр использует временную ссылку на 60 секунд; скачивание выполняется с проверкой доступа аккаунта.
- Файлы не сохраняются в localStorage и не передаются ИИ-помощнику.

Миграция [petcare_documents](supabase/migrations/20261031114537_petcare_documents.sql) применена к подключённому проекту. Для нового окружения выполните её после базовой схемы [supabase_setup.sql](supabase_setup.sql). Миграция предназначена для однократного применения.

## Проверки

- [check-documents.cjs](tools/check-documents.cjs): интерфейс с подменённым клиентом, PDF/PNG, привязка и редактирование, фильтры, открытие/скачивание, сбои загрузки и сохранения, переключение питомца во время операции, удаление и размеры экрана. Запуск через установленный Node; использует существующий Playwright из `.tools/preview` и Chrome.
- [check-documents-rls.sql](tools/check-documents-rls.sql): проверяет доступ владельца и запрет доступа другого аккаунта в транзакции с `ROLLBACK`. Тестовые пользователи и строки не сохраняются.

Полная загрузка файла через реальную сессию владельца проверяется после входа в PetCare. Автотест интерфейса не использует данные владельца.

## Печать оригиналов

У каждого файла есть кнопка «Печать». PDF.js 6.5.438 локально готовит все страницы PDF, а JPEG, PNG и WebP помещаются на лист с сохранением пропорций. В отдельном предварительном просмотре нажмите «Печатать», чтобы выбрать принтер, страницы или сохранение в PDF. Файлы не передаются сторонним просмотрщикам. При выходе из аккаунта и смене питомца открытые окна печати закрываются.

Исходники просмотра: `document-print.js`, `document-print.css`, `document-print.html`. После изменения скрипта или стилей выполните `npm ci --prefix tools` и `npm run --prefix tools build:document-print`: сборка обновит `document-print.bundle.js` и локальные ресурсы PDF.js в `assets/vendor/pdfjs`. Библиотека загружается только при печати PDF.

`tools/check-document-print.cjs` проверяет двухстраничный PDF с портретной и альбомной страницами, точное число печатных страниц, скан, экранирование названий, узкий экран, ошибки загрузки, повреждённый PDF и выход из аккаунта. Проверяются запуск через HTTP и локальный `index.html`. PDF с более чем 100 страницами предлагается печатать через просмотрщик оригинала; частично подготовленные документы не печатаются.
