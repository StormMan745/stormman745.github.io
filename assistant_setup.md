# Подключение PetCare AI

Чат отправляет сообщения в Supabase Edge Function `petcare-assistant`, которая отвечает через GigaChat API. Секреты авторизации хранятся только в Supabase и не передаются браузеру.

## Секреты GigaChat

В Supabase уже настроены секреты `GIGACHAT_AUTH_KEY` и `GIGACHAT_CA_CERT`. Если подключаете другую учётную запись, откройте [секреты Edge Functions](https://supabase.com/dashboard/project/qexiyikdmdbdxgusqnee/functions/secrets) и задайте:

- `GIGACHAT_AUTH_KEY` — ключ авторизации GigaChat API из личного кабинета.
- `GIGACHAT_CA_CERT` — корневой сертификат НУЦ Минцифры в PEM-формате; нужен для проверки TLS-сертификата GigaChat.
- `GIGACHAT_SCOPE` — область API, по умолчанию `GIGACHAT_API_PERS`.
- `GIGACHAT_MODEL` — модель, по умолчанию `GigaChat-2`.

Не помещайте эти значения в `index.html`, `script.js`, репозиторий или чат. Функция получает токен GigaChat на сервере и использует его для генерации ответа.

## Публикация функции из PowerShell

Из корня проекта выполните:

```powershell
& ".\.tools\supabase\supabase.exe" functions deploy petcare-assistant --project-ref qexiyikdmdbdxgusqnee
```

Функция требует активную сессию Supabase; её настройки находятся в `supabase/config.toml`. После публикации войдите в PetCare и отправьте сообщение в раздел «ИИ-помощник».

Переписка и данные питомца сохраняются в аккаунте PetCare. Ответы помощника не заменяют консультацию ветеринара.

## Ответы с учётом профиля

Перед вопросом приложение синхронизирует данные и передаёт идентификатор выбранного питомца. Edge Function проверяет пользователя через Supabase Auth и читает его строку `petcare_data` с пользовательским JWT. Чтение защищено существующими правилами RLS; `service_role` для этого не используется.

В GigaChat передаются только разрешённые текстовые поля выбранного питомца: карточка, возраст и вес, аллергии, постоянные лекарства, клиника, медицинские записи, напоминания, выполненные задачи, история ухода и даты фотоподборок. Содержимое фотографий, сканы, ссылки на приватные файлы, токены и данные других аккаунтов в контекст не включаются.

Небольшая история передаётся целиком. Для большой истории функция ищет подходящие к вопросу записи среди сохранённого текста и сообщает, сколько записей включено в ответный контекст. Сокращения обозначаются, отсутствие записи в частичной выборке не считается подтверждением её отсутствия в профиле.

Новые сообщения помечаются идентификатором питомца; в запрос входят сообщения о выбранном питомце. При смене аккаунта или питомца незавершённый запрос отменяется, а запоздалый ответ не записывается в другую историю. Старые сообщения без привязки к питомцу остаются видны, но не используются как контекст нового запроса.

Изменения серверной функции нужно публиковать в Supabase вместе с обновлением файлов сайта на GitHub Pages. Публикация только в GitHub не обновляет работающую Edge Function.
